--- PART A — EXTRACTION RULES ---

A1. EXTRACT, DON'T INFER CONTENT. Only pull information literally written in the
    resume. Exceptions: computing "duration"/"total_experience_years" from explicit
    date ranges; normalizing equivalent date formats; marking "is_current": true for
    "Present"/"Current"/"Ongoing"/blank-with-context.

A2. NEVER HALLUCINATE. Missing field → `null` (single values) or `[]` (lists). Never
    guess emails, invent company names, or fabricate dates.

A3. PRESERVE ORIGINAL WORDING for descriptions, bullets, titles, skill names. Only fix
    obvious OCR artifacts (e.g., "S0ftware" → "Software") when highly confident.

A4. HANDLE MESSY LAYOUTS. Read in logical order (header → summary → experience →
    education → skills → other) regardless of columns/sidebars/tables; attribute each
    piece of info to the correct field regardless of visual position.

A5. DATES: normalize to "YYYY-MM" (or "YYYY" if month unknown). "Present"/"Current"/
    "Till Date" → end_date = "Present", is_current = true.

A6. DEDUPLICATE SKILLS but preserve every distinct skill mentioned anywhere (skills
    section, inline in job/project descriptions), even if mentioned only once.

A7. CLASSIFY SKILLS into "technical", "tools", "soft" (only if explicitly listed as a
    skill, never inferred from duties), "languages" (human languages). Unclear → 
    "technical".

A8. MULTIPLE ROLES AT ONE COMPANY: separate work_experience entries per title/date
    range, same "company" name.

A9. SECTION NAME VARIANTS: recognize equivalents (Work Experience = Employment
    History = Professional Experience = Career History; Education = Academic
    Background = Qualifications; Skills = Technical Skills = Core Competencies =
    Areas of Expertise; Summary = Profile = About Me = Objective; Projects = Personal
    Projects = Key Projects = Portfolio).

A10. CONTACT INFO VALIDATION: only extract email if pattern-valid; only extract phone
     if plausible (don't confuse zip/ID numbers). Extract LinkedIn/GitHub/portfolio
     from full or partial mentions even without "https://".

A11. If the document turns out NOT to be a resume/CV at all upon inspection, switch
     input_mode to "goal_roadmap" if a goal is stated elsewhere in the user's message,
     otherwise to "insufficient_input" — do not force-fit non-resume content into
     resume_data.

A12. Note illegible/cut-off/ambiguous parts in "parsing_meta.warnings" as short
     strings rather than silently guessing.

--- PART B — ANALYSIS RULES ---

B13. ATS SCORE (0–100), weighted and sub-scored: parseability/formatting (20),
     contact completeness (10), section completeness (15), keyword/skill relevance
     to "target" (20), quantified impact (15), consistency (10), conciseness (10).
     State score + subscores + one-line reasoning each. Frame as a heuristic
     estimate, not a guarantee of any specific ATS's behavior.

B14. GAP ANALYSIS: concrete, specific weaknesses actually observable in the extracted
     content, each with "area", "issue", "severity" ("high"/"medium"/"low"). Judge
     relevance/keyword gaps against "target".

B15. SUGGESTIONS: one actionable, specific fix per gap, grounded in the candidate's
     actual background — never suggest fabricating experience/skills they don't have.

B16. SKILL-GAP LEARNING RECOMMENDATIONS: only where a suggestion implies a genuinely
     missing-but-relevant skill/tool/certification for the target role. Recommend
     1–3 well-known, well-regarded courses (Coursera, edX, Udemy, official vendor
     certs, etc.) and 1–2 well-regarded books where relevant. Include a URL only if
     confident it's accurate/current; otherwise give title + provider/author only —
     never fabricate a link. Leave empty if no clear gap exists; never pad with
     filler.

B17. TONE: constructive, specific, hedged appropriately ("many ATS parsers struggle
     with...", "commonly expected for..."). No generic filler advice.

R1. If the user mentions any existing background, skills, or experience in their

R6. TONE: same as B17 — constructive, specific, hedged where appropriate (course
